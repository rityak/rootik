# Rootik — React UI toolkit

Dark-first UI toolkit for dashboards, panels and desktop clients (Tauri/web). Consumers:
dataset-toolkit (client) and umiray-client — every component exists because
one of them needs it or because a mainstream toolkit (Radix/Mantine/shadcn) has it. Progress: `TODO.md`.

## Stack

- React 19, TypeScript (strict, `noUncheckedIndexedAccess`), Bun, Biome, Ladle for stories.
- **Zero runtime deps** besides React. Icons inside the kit are inline SVG (`src/lib/icons.tsx`);
  consumers pass any `ReactNode` as `icon` (lucide works). `lucide-react` is a dev dep for stories only.
- Plain CSS with custom properties, no Tailwind in the kit. All kit CSS lives in `@layer rootik`.
- Commands: `bun run dev` (Ladle on :61000), `bun run check` (tsc + biome + bun test), `bun run format`.
  CI (`.github/workflows/ci.yml`) runs typecheck, `biome ci`, tests and `ladle build`; Bun version is pinned
  by `packageManager` in package.json.
- Biome is stricter than `recommended` (see biome.json). Kit code (components/lib/theme) may import only peer
  deps; stories may use dev deps. Plugin `biome/untinted-neutral.grit` rejects translucent `oklch(L 0 0 / a)`.
- `bun run build` → `dist/` (tsc per-module ESM + `.d.ts`, one `styles.css`), checked by `scripts/check-dist.ts`.
  Exports resolve `dist/` by default and `src/` under the `source` condition (Vite: `resolve.conditions`).
- `llms.txt` is generated by `scripts/llms.ts` (index of components → file:line, story, JSDoc summary);
  `bun run format` refreshes it and CI fails when it's stale.
- Visual regression is local only: `bun run visual` (Playwright) screenshots every story from the Ladle build
  against per-machine baselines in `visual/__screenshots__` (gitignored); `-- --update-snapshots` rewrites them.
- Release: `npm version <patch|minor>`, `git push --follow-tags`, publish a GitHub Release → `publish.yml`
  runs `npm publish` (npm Trusted Publishing, no token).
- Ladle's own types don't compile under TS 7: tsconfig `paths` maps `@ladle/react` to `.ladle/ladle-types.d.ts`.
- Stories live in `src/stories/*.stories.tsx` (one file per family); preview a single story with
  `?story=<family>--<name>&mode=preview`. Layout stories use `Stage` (stories/stage.tsx): material
  switcher + page/window/phone frame. Ladle only picks up new story files/exports after a restart.

## Gotchas

- Any author `display` on a popover element beats the UA "hide closed popover" rule — `.rk-floating:not(:popover-open)`
  in base.css handles it; keep that class on every popover.
- Token overrides inside a scope must use explicit values: `--rk-text: var(--rk-on-inverse)` next to a redefined
  `--rk-on-inverse` resolves to the *new* value.
- Neutral chroma is scaled per lightness step (equal chroma looks blue on the darkest step and grey on lighter ones).
- Chart palette is validated (dataviz validator, dark band L 0.48–0.67); re-run it when changing `--rk-chart-*`.

## Layout

```
src/
  tokens.css        design tokens (:root) — the only place with raw colors/sizes
  base.css          page base, focus ring, utilities (.rk-num, .rk-hatch, .rk-sr-only)
  styles.css        entry: layer order + @import of every css file
  index.ts          public exports
  lib/              cx, inline icons, floating (popover positioning), hooks
  theme/            appearance model, RootikProvider, AppearanceSettings
  components/       one file per component family (x.tsx + x.css); stories in src/stories/
```

## Rules

- Colors, radii, spacing, durations: **only via `--rk-*` tokens**. No hex in component CSS.
- Class names `rk-<component>[-part]`; variants/state via `data-*` attributes (`data-variant`,
  `data-size`, `data-active`), not modifier classes. Keep selectors flat and low-specificity.
- Props: `variant`, `size` (`sm | md | lg`, default `md`), `tone` (`neutral | accent | success | warn |
  danger | info`), `icon: ReactNode`. Spread rest props to the root element and merge `className`.
- Native first: `<dialog>`, Popover API (`popover` attr) for every floating layer, native inputs with
  `appearance: none`, `<details>`. JS only where the platform has nothing (listbox, positioning).
- Accessibility is not optional: keyboard nav per ARIA APG, labels for icon-only controls,
  `:focus-visible` ring, `prefers-reduced-motion` (tokens zero durations via `--rk-motion`).
- Every component gets a story; stories double as the visual spec. Check new UI in the browser.
- New component → update `TODO.md` and export it from `src/index.ts`. Components built in parallel PRs get
  their own module + story file, registered up front (stub module, `index.ts`/`styles.css` lines) so the PRs
  never edit the same lines; icons a component alone needs are defined locally with `icon()` from lib/icons.
- Code comments: short, in English, only for the non-obvious "why".
- Every string the kit renders itself (aria-labels, placeholders, default copy) comes from `useLabels()`
  (`src/lib/labels.tsx`), so `<RootikProvider labels>` translates it; props only override.
- A control that is only a shape (checkbox, radio, input rim, switch track) draws its boundary with
  `--rk-control-edge` (3:1); `--rk-line` is for dividers. Keyboard focus is the kit ring, never a faint glow.
- Looping animations take their duration from `--rk-dur-slow` / `--rk-motion`, so reduced motion and
  Motion: Off leave a static state. Status by color needs a text alternative (`StatusDot label`,
  `Avatar statusLabel`); toasts with an action or errors don't auto-dismiss.
- Line endings are LF (`.gitattributes`); Biome fails on CRLF.

## Style — "Graphite & Iris"

1. **Graphite canvas, one tint.** Neutrals in OKLCH from two knobs (`--rk-neutral-h`, `--rk-neutral-c`).
   Depth = lightness steps (`bg < surface-1 < surface-2 < surface-3`) + 1px inner top highlight. Every
   neutral carries the tint: surfaces scale chroma with lightness, secondary text is tinted, overlays use
   `oklch(var(--rk-shade) / a)` / `oklch(var(--rk-tint) / a)` and wells use `--rk-well*` — never
   `oklch(0 0 0 / a)` or `oklch(1 0 0 / a)`, those read grey.
2. **One signal accent** (default Iris `oklch(0.57 0.2 277)`, analogous to the neutral hue). Accent =
   primary action, focus, highlighted datum. Never decoration. Fills carry `--rk-on-accent` labels; accent
   as text/icon on dark uses `--rk-accent-text`. Semantic colors (success/warn/danger/info) only for status.
3. **Inverted pill = selected.** Active tab/segment/nav/dock item is a light pill with dark text.
4. **Big light numbers.** KPIs: large, weight 300, tabular, tight tracking; unit/label small and dim.
5. **Hatch = the rest.** Diagonal hatching marks remainder/inactive/placeholder (progress rest, idle
   bars, gauge rest, drop zones).
6. **Soft geometry.** Big card radius, pill or soft controls, concentric radii (inner = outer − pad).
7. **Two layouts.** AppShell `islands` (default): sidebar, header, aside, footer and dock are separate
   `.rk-surface` panels over one ambient canvas, content is transparent and holds cards. `inset`: frame
   parts sit on the background, content + aside are one surface block (`.rk-shell-panel`). The surface
   material (default Veil: 80% + 10px blur, gradient hairline rim) applies to all of them; popovers,
   dialogs and toasts are full glass. Materials live in `MATERIALS` (theme/schema.ts): solid / veil /
   frost / liquid; keep backdrops restrained — low `saturate()`, accent glow ≤ 16%.
8. **Dense, not empty.** Controls 28/34/42px, 13px UI text. Minimalism by hierarchy, not whitespace.
9. **Motion** short (160ms) ease-out; springy only for toggles/indicators.

## Theming

`RootikProvider` owns appearance values (accent, neutral tint, radius, pill, density, font, font size,
glass, motion + consumer extensions) and writes them as CSS vars on `<html>`. `AppearanceSettings`
renders the same schema as a form. Projects extend it with `extensions` — sections of fields, fields can
nest (`children`, shown when the parent is on) and map to CSS vars (`cssVar`) or custom `apply`.
Light theme is not shipped: consumers override tokens (see README).
